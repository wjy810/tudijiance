# 小麦品种实验田数字化管理系统：技术选型（v0.1）

依据 [需求分析 v0.3](需求分析.md)。版本号查询于 2026-10-30，开工时以各项目官方的最新稳定版为准，见第 8 节。

## 1. 结论一览

| 层 | 选型 |
|---|---|
| 前端界面 | Vue 3 + TypeScript + Vite。桌面界面用 Element Plus，手机界面用 Vant 4 |
| 桌面应用 | Electron，用 electron-builder 打 Windows 安装包，用 electron-updater 自动更新 |
| 安卓 APP | Capacitor，和桌面共用同一份 Vue 代码 |
| 图表 | ECharts |
| 实验田平面图编辑 | Konva（vue-konva） |
| 录入网格和汇总表 | VXE Table |
| 自助分析引擎 | Arquero，在客户端执行分析步骤 |
| 仪表板拖拽布局 | grid-layout-plus |
| 离线存储 | IndexedDB，用 Dexie 操作 |
| Excel 导入导出 | ExcelJS |
| 后端 | JDK 25 + Spring Boot 4.1 + Spring Security（JWT）+ MyBatis-Plus |
| 数据库 | MySQL 8.4 LTS，表结构用 Flyway 管理 |
| 接口文档 | springdoc-openapi，前端类型从接口文档自动生成 |
| 照片存储 | 服务器本地磁盘，由 Nginx 提供访问 |
| 部署 | Docker Compose（Nginx + 后端 + MySQL） |
| 阶段二 | MQTT，代理服务器用 Mosquitto，后端用 Eclipse Paho 订阅 |
| 阶段三 | Python 分析服务（pandas、statsmodels、scikit-learn） |

## 2. 选型原则

1. **一份前端代码同时出桌面和安卓。** 需求是先做桌面、再做安卓，两边功能大量重叠。
2. **尽量沿用参考代码的技术栈。** 参考代码用的是 Java + Spring Boot、Vue 3、ECharts、MySQL，沿用可以降低学习成本，部分代码能直接借鉴。
3. **只用成熟、文档多、中文资料多的开源项目。** 不选需要额外学一门语言的方案。
4. **不为大数据量做设计。** 估算一年的数据量：300 个小区 × 约 80 个性状 ≈ 2.4 万条观测值，再加农事、照片和气象记录，规模很小。

## 3. 客户端

### 3.1 跨平台方案

| 方案 | 桌面 | 安卓 | 能复用参考代码的 Vue 和 ECharts | 要学的新语言 | 结论 |
|---|---|---|---|---|---|
| **Electron + Capacitor** | ✓ | ✓ | ✓ | 无 | **选用** |
| Tauri 2 | ✓ | ✓ | ✓ | Rust | 不选。安装包小是优点，但原生部分和安卓构建要配置 Rust 和 Android NDK，出了问题要跨语言排查 |
| Flutter | ✓ | ✓ | ✗，要用 Dart 重写，图表也要换库 | Dart | 不选 |
| uni-app | ✗，不能打包 Windows 桌面程序 | ✓ | 部分 | 无 | 不选 |

- Electron 和 Capacitor 分别是"网页打包成桌面程序"和"网页打包成安卓 APP"使用最广的方案，都只用 JavaScript。
- Electron 的代价是安装包较大（约 100 MB），对实验室电脑来说可以接受。

### 3.2 前端结构

```
client/
  src/
    desktop/     桌面界面（Element Plus）：平面图编辑、录入网格、汇总表、分析、仪表板
    mobile/      手机界面（Vant 4）：田间录入、拍照、查看
    shared/      两端共用：接口调用、数据类型、性状字典、离线同步、计算公式（亩产、成穗率等）
  electron/      Electron 主进程：窗口、打印、自动更新
  android/       Capacitor 生成的安卓工程
```

- 桌面和手机的屏幕差别大，所以界面分开写，业务逻辑放在 `shared/` 里共用。
- 参考代码同时用了 Element Plus 和 Ant Design Vue。本项目桌面端只用 Element Plus。

### 3.3 关键组件

| 功能 | 选型 | 理由 |
|---|---|---|
| 实验田平面图编辑 | **Konva**（vue-konva） | 画布库，自带拖拽、框选所需的命中检测、缩放和平移<br>虚线（对照关系连线）直接支持<br>可以把画布直接导出成 jpg，满足标准 8.4 上报种植图的要求 |
| 图表 | **ECharts** | 参考代码在用。折线、柱状、雷达、热力、时间轴（自定义系列）都支持<br>多个图表可以联动，可以导出图片 |
| 录入网格和汇总表 | **VXE Table** | 可编辑表格，用方向键和回车切换单元格，适合对着纸质记载表快速录入<br>支持合并单元格（附录 B 汇总表要用）和大数据量虚拟滚动 |
| 自助分析 | **Arquero** | JavaScript 数据框库，操作和九数云的处理步骤一一对应：<br>筛选 → filter；分类汇总 → groupby + rollup；计算字段、条件赋值 → derive；数据合并 → join；透视 → pivot；同环比 → 窗口函数 lag<br>分析步骤存成 JSON，可以回看和修改；数据量小，在客户端计算即可 |
| 公式字段 | 自己做公式构建器 | 不让用户直接写代码，而是选字段、运算符和函数，由系统生成 Arquero 表达式 |
| 仪表板布局 | **grid-layout-plus** | Vue 3 的拖拽、缩放网格布局 |
| 离线存储 | **Dexie**（IndexedDB） | Electron 和安卓 WebView 都支持 IndexedDB，一套代码两端通用<br>用来存基础数据、待上传队列和未上传的照片 |
| Excel | **ExcelJS** | 在客户端读写 xlsx，离线也能用<br>用于导入土壤化验、气象、送检结果，导出带格式的汇总表 |
| 打印和 PDF | Electron 自带的打印和 printToPDF | 打印空白田间记载表，导出 PDF 报表 |
| 拍照 | @capacitor/camera | 安卓拍照<br>照片在客户端压缩到 0.3–0.5 MB（标准 8.2） |
| 状态管理、路由、网络请求 | Pinia、Vue Router、axios | 和参考代码一致 |

自助分析不选 DuckDB-WASM：它的 SQL 能力更强，但体积有几十 MB，对安卓端负担重，本项目的数据量也用不上。

### 3.4 离线同步

1. **本地先写**：每条记录在客户端生成 UUID。离线时先写进本地 IndexedDB，同时放进"待上传队列"。
2. **先推后拉**：联网后先推送队列，再拉取上次同步之后服务器上的变更。服务器按 UUID 幂等写入，重复推送不会产生重复数据。
3. **冲突处理**：每条记录带版本号。服务器发现版本不一致时不覆盖，返回冲突，由客户端列出让用户选保留哪一份（需求 4.6）。
4. **照片**：单独上传，失败自动重试。
5. **删除**：用软删除（只标记为已删除），方便同步。

不用现成的同步框架（如 PouchDB、RxDB）。它们要求后端换成特定数据库，或按它们的协议改造后端。本项目要同步的数据结构简单，自己实现更可控。

### 3.5 发布和更新

- **桌面**：electron-builder 打 Windows 安装包，electron-updater 从自己的服务器检查和下载更新。安装包没有代码签名时，Windows 会弹 SmartScreen 警告；校内使用可以接受，以后需要再购买证书。
- **安卓**：打 APK 放在服务器上供下载，不上应用商店。APP 启动时检查版本，有新版本时提示更新。

| 问题 | 处理 |

### 4.3 数据模型

| 表 | 内容 |
|---|---|
| `trial` 试验 | 年度、名称、类型、麦区、重复次数、对照品种 |
| `field` 实验田 | 位置、海拔、经纬度、行列数、土质、水旱地等 |
| `plot` 小区 | 所属实验田、行、列、编号、重复号、面积、行数、行距、是否保护区 |
| `variety` 品种 | 名称、统一编号、选育单位、生态型、品质类型、对照类型 |
| `planting` 种植记录 | 试验 + 小区 + 品种，每年每个小区一条 |
| `control_link` 对照关系 | 小区之间的对照连线 |
| `trait_def` 性状定义 | 附录 D 的属性：数据类型、单位、精度、采集阶段、汇总方法、适用麦区。预设和自定义的项目都存在这里 |
| `trait_option` 分级选项 | 级别值、名称、分级说明（附录 A） |
| `observation` 观测值 | 种植记录、性状、重复、日期、值、来源（手动或传感器）、录入人、版本号、客户端 UUID |
| `operation` 农事操作 | 类型、日期、明细（JSON），以及作用到哪些小区（多对多） |
| `photo` 照片 | 关联的种植记录或异常、拍摄阶段、文件路径 |
| `incident` 异常情况 | 灾害类型、日期、受影响的小区、程度、说明 |
| `soil_sample` 土壤化验 | 取样信息和各项化验值 |
| `weather_daily` 逐日气象 | 气温、降水、日照、湿度、风速 |
| `sensor_reading` 传感器数据 | 阶段二用，按月分区 |
| `user`、`audit_log` | 用户、操作记录 |

- **观测值按类型分列存**：`observation` 用三列分别存数值、文本、日期，不把所有值都当字符串存，这样排序和汇总才正确。
- **汇总值不单独存**：品种汇总值按 `trait_def` 里的汇总方法实时计算。改了原始数据，汇总结果自动更新。
- **附录 D 要整理成种子数据**：附录 D 的 166 个性状和附录 A 的分级选项，要整理成 CSV，再用 Flyway 导入。这项工作要单独安排时间，并逐项对照标准原文校对。

### 4.4 接口

- REST + JSON。按资源划分：试验、实验田、小区、品种、性状、观测值、农事、照片、报表等。
- 离线同步用两个专门的接口：
  - `POST /api/sync/push`：批量推送待上传队列。
  - `GET /api/sync/pull?since=…`：拉取指定位置之后的变更。

## 5. 部署

- **容器**：Docker Compose 运行三个容器：Nginx、后端、MySQL。
- **Nginx**：负责 HTTPS 和反向代理 `/api`，并直接提供照片、桌面安装包、APK 下载。
- **HTTPS**：安卓 9 及以上默认禁止明文 HTTP，所以要启用 HTTPS。有域名可以用 Let's Encrypt 的免费证书。
- **服务器配置**：阶段一 2 核、4 GB 内存、50 GB 硬盘足够。阶段二接入传感器后，按数据量加硬盘。
- **备份**：
  - 每天 mysqldump 一次，照片目录增量同步到另一台机器或网盘，保留 30 天。
  - 定期做一次恢复演练。
- **健康检查**：用 Spring Boot Actuator 的健康检查接口。

## 6. 阶段二、三

这两个阶段先定方向，到时候再细化。

**阶段二（物联网）**

- **MQTT 代理服务器**：用 Mosquitto，独立部署，和后端解耦。
- **后端**：用 Eclipse Paho MQTTv5 客户端订阅数据。
- **传感器接入**：RS485/Modbus 传感器 → 4G DTU 或网关 → MQTT。设备要求见[硬件设备需求](硬件设备需求.md)第 5 节。
- **数据存储**：写入 `sensor_reading` 表，按月分区。这个数据量 MySQL 足够。
- **参考代码**：参考代码的做法是用 Vert.x 在后端内置一个 MQTT 服务器，也可行。但它用的是 Vert.x 4，当前已经是 Vert.x 5，代码要改写。可以借鉴它的主题设计、报文解析、设备认证和告警逻辑。

**阶段三（分析决策）**

- 单独做一个 Python 服务（FastAPI + pandas + statsmodels + scikit-learn），由后端调用。
- 用来做随机区组方差分析、多重比较、品种稳定性分析和品种推荐。
- 如果需要 AMMI、GGE 双标图等品种试验专用方法，R 语言的 agricolae、metan 包更成熟。

## 9. 实施顺序建议

1. **工程骨架**：后端（登录、用户、Flyway）、前端（Electron 外壳和桌面布局）、持续集成。
2. **性状字典**：把附录 D 和附录 A 整理成种子数据并校对。后面所有功能都依赖它，所以排在前面。
3. **实验田平面图编辑器**：网格、编号、品种分配、重复、对照连线、导出种植图。
4. **桌面录入**：试验和品种管理、按性状的录入网格、农事批量登记。
5. **汇总和图表**：汇总计算、标准汇总表（附录 B）、预置图表。
6. **离线同步**。
7. **安卓 APP**：Capacitor 外壳、手机录入界面、拍照。
8. **自助分析和仪表板**。

每一步完成后都是能用的版本，可以先给老师试用。

## 10. 风险和应对

| 风险 | 应对 |
|---|---|
| 九数云式的自助分析范围很大，容易拖慢整体进度 | 先做预置图表和标准汇总表，自助分析放到后面；过渡期把数据导出成 Excel，用九数云分析 |
| 离线同步出错，导致数据丢失或重复 | 客户端 UUID + 幂等写入 + 版本号；保留同步日志；服务器每天备份 |
| 166 个性状的字典整理出错 | 两人交叉校对，逐项对照标准原文 |
| 手机 WebView 性能不够 | 手机端只做录入和查看，平面图编辑和自助分析只在桌面端做 |
| 服务器只能在校内访问 | 田间离线录入，回到校内网络后再同步；先确认服务器的网络情况（第 11 节问题 1） |

## 11. 待确认的问题

1. **服务器**：用什么操作系统、什么配置？有没有公网 IP 或域名？手机在田里用流量能不能访问到？
2. **桌面系统**：桌面应用只需要支持 Windows 吗？（同需求分析第 8 节问题 3）
3. **安卓版本**：要用的安卓手机大概是什么系统版本？这决定 APP 最低支持哪个安卓版本。
4. **开发人员**：由谁开发、几个人？对 Java 和 Vue 熟悉到什么程度？这决定技术栈是否需要再简化。
