# 小麦品种实验田数字化管理系统 技术选型

v0.5 · 2026-10-31 · 依据 [需求分析 v0.6](需求分析.md)

版本号查询于 2026-10-30，开工时以各项目官方的最新稳定版为准，见第 8 节。

## 1. 结论

| 部分 | 选型 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite，一份代码同时出手机 APP、电脑端和大屏页面 |
| 手机 APP（主要录入端） | Capacitor 打包成安卓 APP；界面用 Vant 4 |
| 电脑端 | Electron 打包成 Windows 程序；界面用 Element Plus |
| 大屏展示 | 前端里单独的大屏页面，在大屏电脑上用电脑端程序全屏显示 |
| 图表 | ECharts |
| 实验田平面图 | Konva |
| 离线存储（手机） | IndexedDB，用 Dexie 操作 |
| Excel 导入导出 | 后端用 Apache POI：导入时读 .xlsx、.xls、.csv，导出 .xlsx |
| 后端 | Spring Boot 4.1 + Spring Security（JWT）+ MyBatis-Plus；JDK 21 及以上 |
| 数据库 | MySQL 8.4 LTS，表结构用 Flyway 管理 |
| 部署 | Docker Compose（Nginx + 后端 + MySQL） |
| 自动采集接口（第一期预留） | 统一的入库服务 + HTTP 上报接口；MQTT 接入（Mosquitto + Eclipse Paho）默认关闭 |
| 第三期推荐 | Python 分析服务 |

## 2. 选型理由

- **一份前端代码，三个出口。** 手机录入、电脑管理和大屏展示的功能大量重叠，用 Vue 写一份，分别打包。
- **沿用参考代码的技术栈。** 参考代码用的是 Java + Spring Boot、Vue 3、ECharts、MySQL，沿用可以降低学习成本。
- **只用成熟、资料多的开源项目，不额外学新语言。**

打包方案的比较：

| 方案 | 电脑端 | 安卓 | 能复用 Vue 和 ECharts | 要学的新语言 | 结论 |
|---|---|---|---|---|---|
| **Electron + Capacitor** | ✓ | ✓ | ✓ | 无 | 选用 |
| Tauri 2 | ✓ | ✓ | ✓ | Rust | 不选：安卓构建要配 Rust 和 NDK |
| Flutter | ✓ | ✓ | ✗ | Dart | 不选：要重写 |
| uni-app | ✗ | ✓ | 部分 | 无 | 不选：不能打包 Windows 程序 |

## 3. 客户端

### 3.1 代码结构

```
client/
  src/
    desktop/     电脑界面：首页、平面图、数据查看、统计、品种、录入项目、导入、用户、传感器；
                 大屏页面也在这里（views/ScreenView.vue）
    shared/      共用：接口调用和数据类型、录入值的处理、编号规则、图表样式、导入时猜列的对应关系
    stores/      登录状态、录入项目字典（Pinia）
    mobile/      手机界面：田间录入、查看（未开始）
  electron/      Electron 主进程
  android/       Capacitor 生成的安卓工程（未开始）
```

生育期天数、折合亩产等计算公式放在后端（`server/.../observation/ComputedTraits.java`），各端看到的结果一致。

### 3.2 手机录入

需求要求"能选的尽量选"，对应做法：

- **选小区**：在平面图上点选，可以多选；
- **选项目和取值**：用 Vant 的选择器选品种、操作类型和分级，旁边显示分级标准；
- **日期**：默认当天。

### 3.3 离线同步

1. 手机上每条记录生成唯一编号（UUID），先存进本地 IndexedDB，并放进"待上传队列"。
2. 联网后先上传队列，再拉取服务器上的新数据。服务器按编号去重，重复上传不会产生重复数据。
3. 每条记录带版本号；同一条数据在两处被改时不覆盖，提示用户选择保留哪一份。

### 3.4 发布和更新

- **电脑端**：electron-builder 打 Windows 安装包，electron-updater 从自己的服务器检查更新。
- **安卓**：打 APK 放在服务器上下载，APP 启动时检查新版本。

## 4. 后端

### 4.1 技术栈

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | JDK 21 及以上 | 代码按 21 编译，也能在 25 上运行 |
| 框架 | Spring Boot 4.1 | |
| 持久层 | MyBatis-Plus 3.5 | 沿用参考代码 |
| 数据库 | MySQL 8.4 LTS | 沿用参考代码 |
| 表结构管理 | Flyway | 表结构变更写成带版本号的脚本 |

| 接口文档 | springdoc-openapi | 后端启动后打开 `/swagger-ui.html`；前端的数据类型目前手写在 `client/src/shared/api/types.ts` |
| Excel | Apache POI 5.4 | 历史表格导入、数据和汇总表导出 |

### 4.2 用户和权限

按需求分析 3.1 的四级用户：

| 角色 | 代码 | 后端权限 |
|---|---|---|
| 系统管理员 | `SYS_ADMIN` | 只能调用用户管理、功能模块管理、系统维护的接口；调用数据的新增、修改接口时拒绝 |
| 老师 | `TEACHER` | 数据的录入、查看、修改、删除；实验田、品种设置；导入 |
| 学生 | `STUDENT` | 录入和查看 |
| 游客 | `GUEST` | 只能调用大屏用的只读接口 |

- 每个接口用 `@PreAuthorize` 标明哪些角色能调用。
- 数据的修改和删除都写进操作记录表 `audit_log`。
- 功能模块的增加、删除、停用（未实现）：计划把模块列表存在数据库里，前端按它显示菜单，后端按它放行接口。

### 4.3 数据模型

| 表 | 内容 |
|---|---|
| `app_user` | 用户和角色 |
| `field`、`plot` | 实验田（地点、经纬度、海拔、面积、土质、水地或旱地、前茬作物）和小区网格（编号、类型、长宽、行数、行距） |
| `variety` | 品种（编号、选育单位、冬春性、品质类型、对照类型） |
| `trial`、`planting` | 每年的试验（类型、麦区、重复次数），以及小区种的品种、重复号和异常标记 |
| `control_link`、`control_link_plot` | 对照关系（平面图上的虚线） |
| `trait_def`、`trait_option` | 录入项目和分级选项：标准项目、农事操作、自定义项目都在这里，属性参照 NY/T 1301—2025 附录 D |
| `observation` | 录入的数据：种植记录、项目、日期、值、来源（手动、表格导入、传感器）、录入人、版本号、客户端 UUID |
| `audit_log` | 录入数据的修改和删除记录 |
| `device`、`sensor_metric`、`sensor_reading` | 自动采集预留：设备、测量项、读数 |

- 农事操作没有单独建表，作为一类录入项目存在 `observation` 里；一次作用到多个小区时，每个小区存一条。
- 原计划的 `import_template` 没有建：导入时按表头自动猜列的对应关系，不保存。
- 需求分析 3.3 里的土壤化验结果和气象数据还没有对应的表。`observation` 按"种植记录"（试验 + 小区）存，而土壤化验一般按地块和取样日期记，气象数据按日期记，要另外设计。

### 4.4 历史表格导入

已实现，菜单"导入历史表格"（老师），平面图的"更多"里也有入口：

1. 老师在电脑端选择文件上传，后端用 Apache POI 读 .xlsx、.xls、.csv（CSV 自动识别 UTF-8 和 GBK），返回前 40 行预览。
2. 对应各列：小区编号、品种、重复、调查日期和各录入项目。页面按表头自动选好（"株高(cm)""穗数""亩产""播期"等常见写法），不对的可以手动改。
3. 找小区：按小区编号找；没有编号时，按品种 + 重复在这一年的布局里找。有编号时，可以按表格设置这一年的品种和重复；品种表里没有的品种可以自动新增。
4. 按项目类型解析值：日期支持"2025-10-12""2025年10月12日""10月12日"（按试验年份补全）等写法；分级可以写"3级""中抗"；"78.5cm"按数字读。折合亩产按小区面积换算成小区产量保存。
5. 先检查再导入：列出每个有问题的格子（第几行、哪一列、什么问题）。同一份表格重复导入不会产生重复数据。来源记为"表格导入"，修改记录里能看到。
6. 可以下载导入模板，里面已经填好这个试验各小区的编号、品种和重复。

现在是按常见写法做的，拿到老师的样表后再核对一遍。

### 4.5 预留的自动采集接口

老师的意见是：第一期只留接口，采集哪些数据、什么格式到第二期再定。现在留的接口：

- **统一入库服务**：所有自动采集的数据都从这里进库，负责校验、去重、标记超范围数值、更新设备在线状态。
- **HTTP 上报接口**：`POST /api/ingest/devices/{设备编号}/readings`，用设备令牌校验。
- **MQTT 接入**：默认关闭，第二期需要时打开。
- **报文解析接口** `PayloadDecoder`：现在支持 JSON；第二期定下报文格式后，加一个解析类就行。
- **测量项表** `sensor_metric`：已预置土壤温度、湿度、pH 等，新增测量项只需加一行数据。
- **数据模拟器**：没有硬件时用来测试接口和图表，正式环境关闭。

### 4.6 从参考代码复制时要处理的问题

| 问题 | 处理 |
|---|---|
| springfox 已停止维护，不兼容 Spring Boot 3 及以上 | 换成 springdoc-openapi |
| fastjson 1.2.76 有已公开的反序列化漏洞 | 去掉，统一用 Jackson |
| 引入了 javax.servlet-api，和 jakarta 包冲突 | 去掉 |
| Druid 监控台开着，账号是 admin/root | 不用 Druid |
| 数据库密码、MQTT 服务器地址写死在代码里 | 改成配置项和环境变量 |
| 前端用 Vue CLI，混用 Element Plus 和 Ant Design Vue | 换成 Vite，只用 Element Plus |

## 5. 部署

- Docker Compose 运行 Nginx、后端、MySQL 三个容器。Nginx 负责 HTTPS，并提供安装包和 APK 下载。
- 安卓 9 及以上默认禁止明文 HTTP，要启用 HTTPS；有域名可以用 Let's Encrypt 的免费证书。
- 服务器最好能从外网访问，手机在田里就能直接上传；不能的话，回到校内网络再同步。
- 每天备份一次数据库，保留 30 天，并定期做恢复演练。

## 6. 第二期、第三期

- **第二期（自动采集）**：数据和格式确定后，打开 MQTT 接入或使用 HTTP 接口；照片用 @capacitor/camera 拍摄、压缩后上传。
- **第三期（品种推荐）**：单独做 Python 分析服务（pandas、statsmodels、scikit-learn），做多年汇总、品种稳定性分析和推荐。

## 7. 开发环境

- 后端用 IntelliJ IDEA，前端用 VS Code，打 APK 用 Android Studio。
- 运行环境：JDK 21 或 25、Node.js 22 及以上 + pnpm、MySQL 8。
- 测试：后端用 JUnit；前端用 Vitest。
- 代码放在 GitHub，目前直接提交到 main 分支。提交前跑一遍后端 `mvn test`、前端 `pnpm test` 和 `pnpm type-check`。

## 11. 风险和应对

| 风险 | 应对 |
|---|---|
| 历史表格的格式不统一，导入工作量大 | 先拿样表；导入时按表头自动选列的对应关系，可以手动改，先检查再导入 |
| 离线同步出错，导致数据丢失或重复 | 客户端 UUID + 服务器去重 + 版本号；每天备份 |
| 性状字典整理有错 | 两人交叉校对，对照标准原文 |
| 自动采集的数据和格式未定，预留的接口不合用 | 入库服务、报文解析、测量项都可以扩展，第二期按实际格式补充 |
