# 小麦品种实验田数字化管理系统 技术选型

v0.8 · 2026-11-04 · 依据 [需求分析 v0.6](需求分析.md)

版本号查询于 2026-10-30，开工时以各项目官方的最新稳定版为准，见第 8 节。

## 1. 结论

| 部分 | 选型 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite，一份代码同时出手机 APP、电脑端和大屏页面 |
| 手机 APP（主要录入端） | Capacitor 打包成安卓 APP；界面用 Vant 4 |
| 电脑端 | Electron 打包成 Windows 程序；界面用 Element Plus |
| 大屏展示 | 前端里单独的大屏页面，在大屏电脑上用电脑端程序全屏显示 |
| 图表 | ECharts；自助分析页面可以自己选范围、分组、指标和图表类型 |
| 实验田平面图 | Konva |
| 离线存储（手机） | IndexedDB，用 Dexie 操作 |
| Excel 导入导出 | 后端用 Apache POI：导入时读 .xlsx、.xls、.csv，导出 .xlsx |
| 后端 | Spring Boot 4.1 + Spring Security（JWT）+ MyBatis-Plus；JDK 21 及以上 |
| 数据库 | MySQL 8.4 LTS，表结构用 Flyway 管理 |
| 部署 | Docker Compose（Nginx + 后端 + MySQL） |
| 自动采集接口（第一期预留） | 统一的入库服务 + HTTP 上报接口；MQTT 接入（Mosquitto + Eclipse Paho）默认关闭 |
| 第三期推荐 | Python 分析服务 |

## 2. 选型理由

- **一份前端代码，三个出口。** 手机录入、电脑管理和大屏展示的功能大量重叠，用 Vue 写一份，分别打包。
- **沿用参考代码的技术栈。** 参考代码用的是 Java + Spring Boot、Vue 3、ECharts、MySQL，沿用可以降低学习成本。
- **只用成熟、资料多的开源项目，不额外学新语言。**

打包方案的比较：

| 方案 | 电脑端 | 安卓 | 能复用 Vue 和 ECharts | 要学的新语言 | 结论 |
|---|---|---|---|---|---|
| **Electron + Capacitor** | ✓ | ✓ | ✓ | 无 | 选用 |
| Tauri 2 | ✓ | ✓ | ✓ | Rust | 不选：安卓构建要配 Rust 和 NDK |
| Flutter | ✓ | ✓ | ✗ | Dart | 不选：要重写 |
| uni-app | ✗ | ✓ | 部分 | 无 | 不选：不能打包 Windows 程序 |

## 3. 客户端

### 3.1 代码结构

```
client/
  src/
    desktop/     电脑界面：首页、平面图、数据查看、统计、自助分析、品种、录入项目、导入、用户、传感器；
                 大屏页面也在这里（views/ScreenView.vue）
    shared/      共用：接口调用和数据类型、录入值的处理、编号规则、图表样式、
                 导入时猜区域和字段（importGuess.ts）、自助分析的图表生成（analysis.ts）
    assets/art/  界面用的插画、纹理、图标（生图后处理成 webp/jpg）
    stores/      登录状态、录入项目字典（Pinia）
    mobile/      手机界面：页面（views）、组件（平面图、录入、数字键盘）、本机数据库（db.ts）、
                 先服务器后缓存的取数（repo.ts）、待上传队列（outbox.ts）、同步状态（stores/sync.ts）
    tokens.css   两端共用的颜色、字体变量
  mobile/        手机端的 Vite 入口（index.html），vite.mobile.config.ts 打包到 dist-mobile
  electron/      Electron 主进程；after-pack.cjs 给 Windows 的 exe 写图标和版本
  build/         安装包图标（icon.ico、icon.png）
  scripts/       打 Windows 安装包的脚本（dist-win.mjs、wine-shim）；生成安卓图标的 android-res.py
  android/       Capacitor 生成的安卓工程（capacitor.config.ts 是它的配置）
```

界面风格叫"麦田手记"：米色纸张底纹、深林绿侧栏、麦穗金点缀，标题用思源宋体（`@fontsource/noto-serif-sc` 的粗体，只打包 woff2，按字符分片加载，见 `src/fonts.css`）。颜色、圆角、阴影定义在 `src/tokens.css`，电脑端在 `src/styles.css` 里覆盖 Element Plus 的主题色，手机端在 `src/mobile/mobile.css` 里覆盖 Vant 的主题色。插画和纹理是用生图模型生成后裁剪、压缩的。

生育期天数、折合亩产等计算公式放在后端（`server/.../observation/ComputedTraits.java`），各端看到的结果一致。

### 3.2 手机录入

手机端用 Vant 4，老师、学生登录（系统管理员、游客登录后提示去电脑端、大屏）。底部四个标签：首页、平面图、记录、我的。

- **选小区**：平面图上点小区选中或取消，点行号、列号选整行、整列，"同品种"选上同一品种的各个重复，也可以全选；格子够大，可以缩放、横竖滑动；长按小区看详情。绿点是今天录过，橙点是还没传上去。
- **选项目**：最近用过的排在最前面，可以搜索，也可以按分类左右滑动找。
- **填值**：分级项目做成大牌子，级别下面直接写分级标准；选项、农事类型是大按钮；数字用 APP 自带的数字键盘（按项目的小数位数决定有没有小数点），不用调出系统输入法；日期一点"今天""昨天""前天"。
- **两种方式**：选了多个小区时，可以"所有小区同一个值"一次录完（例如同一天施肥），数值项目也可以"逐个小区录"：一个个小区地填，按"下一个"自动跳到下一个小区（例如量株高）。
- **日期**：调查日期默认当天，可以改。

### 3.3 离线同步

1. 手机上每次录入（一个项目、一个值、一个或多个小区）先存进本机 IndexedDB 的待上传队列（`outbox`），每个小区一个客户端编号（UUID），记下录入人。
2. 打开 APP、网络恢复、回到前台、每分钟一次、刚录完时，按录入的先后上传。服务器按编号去重，上传到一半断网、再传一次也不会重复。
3. 没网时停下等下次；登录过期时停下，重新登录后接着传；服务器不收的（例如项目已停用）标成"没传上去"并写明原因，可以重试或删掉。只上传当前登录账号自己录的。
4. 实验田、试验布局、小区状态、录入项目、品种都是先找服务器，取到了存一份在本机（`cache`），没网时用本机这份，页面上提示"看到的是什么时候的数据"。出发前在"我的"里点"下载离线数据"，把每块地最近一个试验都存到手机上。
5. 手机端登录的令牌 30 天有效（`app.jwt.mobile-ttl`），田里几天没信号也能一直录。
6. 手机上只录入、查看；修改、删除已经上传的数据在电脑端（老师）做，所以不会出现两处同时修改同一条数据的冲突。

### 3.4 发布和更新

- **电脑端**：`pnpm dist:win` 用 electron-builder 打 Windows 安装包（NSIS，可选安装目录，建桌面快捷方式），输出在 `client/release/`。
  - 在 Linux、macOS 上也能打，不用装 wine：exe 的图标和版本信息由 `electron/after-pack.cjs` 用纯 JavaScript 的 resedit 写入；
    electron-builder 用 wine 取卸载程序的那一步，由 `scripts/wine-shim` 改用它自带的 UninstallerReader 完成。
  - 页面用到的库（Vue、Element Plus、ECharts、字体）都由 Vite 打进 `dist/`，所以都放在 devDependencies，安装包里不再带 node_modules。
  - electron-updater 自动更新还没接。
- **安卓**：`pnpm android:apk` 先打包手机端页面，`cap sync` 到安卓工程，再用 Gradle 生成调试版 APK（`client/android/app/build/outputs/apk/debug/app-debug.apk`）。需要 JDK 21 和 Android SDK（平台 36、构建工具 36），在 `client/android/local.properties` 里写 `sdk.dir`。
  - 网络请求走原生 HTTP（CapacitorHttp），不受跨域限制，也能连 http 的服务器（`usesCleartextTraffic`）。最低安卓 7.0。
  - 图标和启动画面由 `python3 scripts/android-res.py` 从 `build/icon.png` 生成。
  - 现在是调试签名的测试版。正式发给大家之前要建一个发布用的签名证书（自己保管好，以后的更新都要用同一个），打 release 版；APP 内检查新版本还没做。

### 4.2 用户和权限

按需求分析 3.1 的四级用户：

| 角色 | 代码 | 后端权限 |
|---|---|---|
| 系统管理员 | `SYS_ADMIN` | 只能调用用户管理、功能模块管理、系统维护的接口；调用数据的新增、修改接口时拒绝 |
| 老师 | `TEACHER` | 数据的录入、查看、修改、删除；实验田、品种设置；导入 |
| 学生 | `STUDENT` | 录入和查看 |
| 游客 | `GUEST` | 只能调用大屏用的只读接口 |

- 每个接口用 `@PreAuthorize` 标明哪些角色能调用。
- 数据的修改和删除都写进操作记录表 `audit_log`。
- 功能模块的增加、删除、停用（未实现）：计划把模块列表存在数据库里，前端按它显示菜单，后端按它放行接口。

### 4.3 数据模型

| 表 | 内容 |
|---|---|
| `app_user` | 用户和角色 |
| `field`、`plot` | 实验田（地点、经纬度、海拔、面积、土质、水地或旱地、前茬作物、区块布局 `layout`）和小区（编号、类型、长宽、行数、行距；"拉平"后的行号列号） |
| `variety` | 品种（编号、选育单位、冬春性、品质类型、对照类型） |
| `trial`、`planting` | 每年的试验（类型、麦区、重复次数、计产用的收获面积），以及小区种的品种、重复号和异常标记 |
| `trial_book` | 试验记载本：封面、试验设计、栽培管理、产量计算参数、气象资料、品种评价（JSON，字段见 `client/src/shared/recordBook.ts`） |
| `control_link`、`control_link_plot` | 对照关系（平面图上的虚线） |
| `trait_def`、`trait_option` | 录入项目和分级选项：标准项目、农事操作、自定义项目都在这里，属性参照 NY/T 1301—2025 附录 D |
| `observation` | 录入的数据：种植记录、项目、日期、值、来源（手动、表格导入、传感器）、录入人、版本号、客户端 UUID |
| `audit_log` | 录入数据的修改和删除记录 |
| `trait_alias` | 录入项目的表头别名：导入表格时按它认出各列（见 4.4） |
| `analysis_chart` | 自助分析里保存的图表，设置以 JSON 原样保存（见 4.5） |
| `device`、`sensor_metric`、`sensor_reading` | 自动采集预留：设备、测量项、读数 |

- 农事操作没有单独建表，作为一类录入项目存在 `observation` 里；一次作用到多个小区时，每个小区存一条。
- 原计划的 `import_template` 没有建，改成按录入项目记表头别名（`trait_alias`）：同一种写法的表头，不管在哪份表格里都能认出来。
- **区块布局**存在 `field.layout`（JSON）：区块网格的行高列宽、单位、合并、区块（类型、特殊大小 `fit`、里面的小区网格和每格对应的小区 id）、真北方向。
  保存布局时服务器按布局增删、更新 `plot`（`FieldService.saveLayout`）；手机端、大屏、导入照旧用"拉平"后的行号列号（`LayoutGeometry.flatten`）。
  以前按行列建的实验田读出来是一个区块（`LayoutGeometry.legacy`）。详见[地块布局与记载本](地块布局与记载本.md)。
- 需求分析 3.3 里的气象数据现在按试验存在记载本的气象资料表里（旬、月，当年和常年）；按日期的自动气象数据、土壤化验结果还没有对应的表。`observation` 按"种植记录"（试验 + 小区）存，而土壤化验一般按地块和取样日期记，气象数据按日期记，要另外设计。

### 4.4 历史表格导入

菜单"导入历史表格"（老师），平面图的"更多"里也有入口。分四步：选择文件 → 整理表格 → 检查 → 完成。

1. **选文件**：选好实验田和试验，上传 .xlsx、.xls 或 .csv（CSV 自动识别 UTF-8 和 GBK）。后端用 Apache POI 读出整张表（最多 5000 行、200 列）给页面。
2. **整理表格**：页面像 Excel 一样显示整张表。
   - **选区域**：拖动鼠标框出数据所在的区域，也可以点"自动识别"（跳过标题行，找到表头和最后一行数据）。
   - **定方向**：每列一个字段（第一行是表头，每行一个小区），或者每行一个字段（第一列是表头，每列一个小区）。页面按"品种""小区""重复"出现在哪儿自动猜。
   - **对应字段**：每个字段对应到"小区编号、品种、重复、调查日期"或某个录入项目。先按录入项目里记下的**表头别名**认，再按项目名称和常见叫法（"株高(cm)""穗数""亩产""播期"等）猜，不对的可以改。
   - **新建项目**：录入项目里没有的字段，点"+"按表头新建自定义项目；类型（数值、日期、选项、文字）、单位、小数位、选项按表头和这一列的值猜好，表头同时记成新项目的别名。
   - **改格子**：双击格子直接改；改过的格子标金色小三角，随请求提交，导入前套用，原表格不动。
3. **检查**（只检查不写入）：列出每个有问题的格子（第几行、哪一列、什么问题），点"去改"回到表格并定位到这个格子。
4. **导入**：按小区编号找小区，没有编号时按"品种 + 重复"在这一年的布局里找；有编号时可以按表格设置这一年的品种和重复，品种表里没有的品种可以自动新增。值按项目类型解析：日期支持"2025-10-12""2025年10月12日""10月12日"（按试验年份补全）等写法；分级可以写"3级""中抗"；"78.5cm"按数字读；折合亩产按小区面积换算成小区产量保存。同一份表格重复导入不会产生重复数据；来源记为"表格导入"，修改记录里能看到。勾选"记住表头对应关系"时，这次确认过的"表头 → 录入项目"记成别名，下次自动认出。

**和录入项目联动**：录入项目页面有"导入时的表头"一列，老师可以增删别名，也可以按名称或表头搜索项目。

另外可以下载导入模板，里面已经填好这个试验各小区的编号、品种和重复。

后端代码：`ImportTable`（区域、方向、改过的格子）、`PlotLocator`（找小区，查找表只建一次）、`ValueParser`（按项目类型解析）、`ImportService`（编排）。

### 4.5 自助分析

菜单"自助分析"（老师、学生）。

- **范围**：实验田、年份（可多选）、品种、重复；在平面图上框选小区后点"做图表"，只看这些小区。
- **分组**（最多两个）：品种、年份、重复、小区、实验田，或者某个分级、选项类项目的取值（如"条锈病反应型"）。第一个分组做横轴，第二个按颜色分系列。
- **指标**（最多 8 个）：数值、分级和计算项目（全生育期、成穗率、折合亩产等），汇总方式可选平均、最大、最小、中位数、合计、个数、变异系数；也可以数小区个数。不分组时每个小区一行，用来画散点图、看明细。
- **图表**：柱状、条形、堆积柱、折线、面积、饼图、环形、散点、雷达、热力图、数据表。设置不够画某种图时直接提示缺什么。
- **常用分析**：各品种亩产对比、历年亩产变化、产量稳定性（变异系数）、条锈病反应型分布、株高和产量的关系、品种性状雷达、品种 × 年份热力图，一点就出图。
- **保存和导出**：图表设置可以保存（大家都能看，建的人或老师可以改、删）；可以导出图片和 Excel。

接口：`POST /api/analysis/query`、`POST /api/analysis/export`、`/api/analysis/charts`。取值规则和统计页面一样：每个小区每年取最近一次录的值，计算项目现算；多个试验、多个项目一次查询。

### 4.6 预留的自动采集接口

老师的意见是：第一期只留接口，采集哪些数据、什么格式到第二期再定。现在留的接口：

- **统一入库服务**：所有自动采集的数据都从这里进库，负责校验、去重、标记超范围数值、更新设备在线状态。
- **HTTP 上报接口**：`POST /api/ingest/devices/{设备编号}/readings`，用设备令牌校验。
- **MQTT 接入**：默认关闭，第二期需要时打开。
- **报文解析接口** `PayloadDecoder`：现在支持 JSON；第二期定下报文格式后，加一个解析类就行。
- **测量项表** `sensor_metric`：已预置土壤温度、湿度、pH 等，新增测量项只需加一行数据。
- **数据模拟器**：没有硬件时用来测试接口和图表，正式环境关闭。

### 4.7 从参考代码复制时要处理的问题

| 问题 | 处理 |
|---|---|
| springfox 已停止维护，不兼容 Spring Boot 3 及以上 | 换成 springdoc-openapi |
| fastjson 1.2.76 有已公开的反序列化漏洞 | 去掉，统一用 Jackson |
| 引入了 javax.servlet-api，和 jakarta 包冲突 | 去掉 |
| Druid 监控台开着，账号是 admin/root | 不用 Druid |
| 数据库密码、MQTT 服务器地址写死在代码里 | 改成配置项和环境变量 |
| 前端用 Vue CLI，混用 Element Plus 和 Ant Design Vue | 换成 Vite，只用 Element Plus |

## 5. 部署

- Docker Compose 运行 Nginx、后端、MySQL 三个容器。Nginx 负责 HTTPS，并提供安装包和 APK 下载。
- 安卓 9 及以上默认禁止明文 HTTP，要启用 HTTPS；有域名可以用 Let's Encrypt 的免费证书。
- 服务器最好能从外网访问，手机在田里就能直接上传；不能的话，回到校内网络再同步。
- 每天备份一次数据库，保留 30 天，并定期做恢复演练。

## 6. 第二期、第三期

- **第二期（自动采集）**：数据和格式确定后，打开 MQTT 接入或使用 HTTP 接口；照片用 @capacitor/camera 拍摄、压缩后上传。
- **第三期（品种推荐）**：单独做 Python 分析服务（pandas、statsmodels、scikit-learn），做多年汇总、品种稳定性分析和推荐。

## 7. 开发环境

- 后端用 IntelliJ IDEA，前端用 VS Code，打 APK 用 Android Studio。
- 运行环境：JDK 21 或 25、Node.js 22 及以上 + pnpm、MySQL 8。
- 测试：后端用 JUnit；前端用 Vitest。
- 代码放在 GitHub，目前直接提交到 main 分支。提交前跑一遍后端 `mvn test`、前端 `pnpm test` 和 `pnpm type-check`。

## 11. 风险和应对

| 风险 | 应对 |
|---|---|
| 历史表格的格式不统一，导入工作量大 | 先拿样表；能框选区域、按行或按列导入，页面上直接改格子；确认过的表头记成录入项目的别名，下次自动认出；先检查再导入 |
| 离线同步出错，导致数据丢失或重复 | 客户端 UUID + 服务器去重 + 版本号；每天备份 |
| 性状字典整理有错 | 两人交叉校对，对照标准原文 |
| 自动采集的数据和格式未定，预留的接口不合用 | 入库服务、报文解析、测量项都可以扩展，第二期按实际格式补充 |
